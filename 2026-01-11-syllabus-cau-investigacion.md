#### 2. Modelos Disponibles en 2026

|Modelo|Desarrollador|Características principales|Acceso|
|---|---|---|---|
|ChatGPT (GPT-4)|OpenAI|Razonamiento avanzado, multimodal|Freemium|
|Grok|xAI|Acceso a datos en tiempo real|Suscripción|
|Gemini|Google|Integración con Google Workspace|Gratuito|
|Claude|Anthropic|Contexto largo (200K tokens)|Freemium|
|Llama 3.3|Meta|Open source, auto-hospedable|Gratuito|

**Comparación de capacidades:**

- **Multimodalidad:** Texto, imágenes, audio
- **Longitud de contexto:** Varía entre 8K-200K tokens
- **Especialización:** Algunos modelos optimizados para código, otros para análisis

#### 3. Principios Éticos Fundamentales

**Transparencia en el uso de IA:**

- Declarar siempre cuando se usa IA
- Documentar prompts utilizados
- Distinguir entre contenido humano y generado por IA

**Privacidad y protección de datos:**

- No compartir información sensible con IA
- Entender las políticas de privacidad de cada plataforma
- Considerar implicaciones de datos personales

**Detección y mitigación de sesgos:**

- Reconocer que los modelos pueden tener sesgos
- Verificar información de múltiples fuentes
- Cuestionar respuestas que parezcan sesgadas

**Responsabilidad académica:**

- La IA es una herramienta, no sustituye el pensamiento crítico
- Verificar siempre los hechos generados por IA
- Citar apropiadamente el uso de IA (según APA 7)


**Mejores prácticas:**

- Ser específico y claro
- Proporcionar contexto relevante
- Indicar el formato deseado
- Usar lenguaje directo

## Clase 3: Prompt Engineering - Anatomía y Frameworks Básicos (1-4)

**Fecha:** ___________  
**Estado:** [ ] Pendiente [ ] En progreso [ ] Completada

### Objetivos de Aprendizaje

- Dominar la anatomía completa de un prompt efectivo
- Aplicar los primeros 4 frameworks de prompt engineering
- Desarrollar prompts específicos para diferentes tipos de tareas
- Construir una biblioteca inicial de prompts personalizados

### Contenidos

#### 1. Anatomía de un Prompt Efectivo

**Modelo completo de 5 componentes:**

```
[ROL] + [TAREA] + [CONTEXTO] + [FORMATO] + [RESTRICCIONES]
```

**Desglose detallado:**

**ROL:** ¿Quién debe actuar la IA?

```
Ejemplos:
- "Actúa como un economista especializado en desarrollo regional"
- "Eres un tutor de estadística para estudiantes universitarios"
- "Comportate como un revisor de papers académicos"
```

**TAREA:** ¿Qué debe hacer exactamente?

```
Ejemplos:
- "Analiza los indicadores económicos de..."
- "Explica el concepto de regresión lineal..."
- "Revisa este abstract y sugiere mejoras..."
```

**CONTEXTO:** Información de fondo relevante

```
Ejemplos:
- "Considerando que soy estudiante de primer año sin conocimientos previos..."
- "Dado que esta investigación se centra en Ayacucho, Perú..."
- "Tomando en cuenta las limitaciones de tiempo (4 semanas)..."
```

**FORMATO:** ¿Cómo debe estructurarse la respuesta?

```
Ejemplos:
- "Responde en forma de lista numerada con 5 puntos"
- "Estructura tu respuesta en: Introducción, Desarrollo, Conclusión"
- "Proporciona una tabla comparativa con ventajas y desventajas"
```

**RESTRICCIONES:** Límites y especificaciones

```
Ejemplos:
- "No uses tecnicismos avanzados"
- "Máximo 300 palabras"
- "Solo fuentes posteriores a 2020"
- "Enfócate en el contexto peruano"
```

#### 2. Framework 1: RTF (Role-Task-Format)

**Estructura:**

```
ROLE: [Define el rol de la IA]
TASK: [Especifica la tarea exacta]
FORMAT: [Indica el formato de salida]
```

**Cuándo usarlo:**

- Tareas simples y directas
- Cuando el contexto es evidente
- Respuestas rápidas

**Ejemplo aplicado a Medicina:**

```
ROLE: Actúa como un médico general
TASK: Explica qué es la hipertensión arterial y sus factores de riesgo
FORMAT: Responde en 3 párrafos: definición, causas, consecuencias
```

**Ejemplo aplicado a Economía:**

```
ROLE: Eres un analista económico
TASK: Resume los efectos de la inflación en el poder adquisitivo
FORMAT: Lista de 5 puntos con ejemplos concretos del Perú
```

#### 3. Framework 2: APE (Action-Purpose-Expectation)

**Estructura:**

```
ACTION: [Qué acción debe realizar]
PURPOSE: [Para qué propósito]
EXPECTATION: [Qué esperas como resultado]
```

**Cuándo usarlo:**

- Generación de ideas creativas
- Planificación de proyectos
- Definición de objetivos

**Ejemplo aplicado a Ingeniería:**

```
ACTION: Genera ideas para un proyecto de ingeniería civil
PURPOSE: Solucionar problemas de infraestructura vial en Ayacucho
EXPECTATION: 10 ideas innovadoras, viables y de bajo costo, con breve descripción de cada una
```

**Ejemplo aplicado a Humanidades:**

```
ACTION: Diseña un plan de investigación
PURPOSE: Analizar la evolución del quechua en la región de Ayacucho (1990-2025)
EXPECTATION: Estructura metodológica con fuentes primarias y secundarias, cronograma tentativo
```

#### 4. Framework 3: CHAT (Context-History-Action-Task)

**Estructura:**

```
CONTEXT: [Contexto actual]
HISTORY: [Antecedentes relevantes]
ACTION: [Acción a realizar]
TASK: [Tarea específica]
```

**Cuándo usarlo:**

- Análisis de problemas complejos
- Situaciones con antecedentes importantes
- Continuidad en conversaciones largas

**Ejemplo aplicado a Ciencias Sociales:**

```
CONTEXT: Estoy investigando migración interna en Perú
HISTORY: Ya revisé datos del INEI de 2015-2020 sobre flujos migratorios de Ayacucho a Lima
ACTION: Analiza las causas económicas de esta migración
TASK: Identifica 5 factores económicos principales con evidencia estadística
```

**Ejemplo aplicado a Matemáticas:**

```
CONTEXT: Estoy aprendiendo cálculo diferencial
HISTORY: Ya domino límites y continuidad, pero tengo dificultades con derivadas
ACTION: Explícame el concepto de derivada
TASK: Usa ejemplos visuales y progresa desde definición básica hasta regla de la cadena
```

#### 5. Framework 4: ROSES (Role-Objective-Scenario-Expected Solution)

**Estructura:**

```
ROLE: [Rol específico de la IA]
OBJECTIVE: [Objetivo a alcanzar]
SCENARIO: [Escenario o situación]
EXPECTED SOLUTION: [Tipo de solución esperada]
```

**Cuándo usarlo:**

- Resolución de problemas complejos
- Simulaciones y casos de estudio
- Planificación estratégica

**Ejemplo aplicado a Administración:**

```
ROLE: Eres un consultor de negocios especializado en PYMEs
OBJECTIVE: Ayudar a una pequeña empresa textil de Ayacucho a aumentar sus ventas en 30%
SCENARIO: Empresa familiar, 5 empleados, producción artesanal, sin presencia digital
EXPECTED SOLUTION: Plan de acción detallado en 5 etapas con costos estimados y cronograma
```

**Ejemplo aplicado a Educación:**

```
ROLE: Actúa como un diseñador instruccional
OBJECTIVE: Crear un plan de clase efectivo sobre pensamiento crítico
SCENARIO: Estudiantes universitarios de primer año, clase de 2 horas, aula presencial
EXPECTED SOLUTION: Estructura de clase con actividades, tiempos, recursos y evaluación
```

### Objetivos de Aprendizaje

### Contenidos

#### 1. Framework 5: LangGPT (Language-Goal-Process-Tone)

**Estructura:**

```
LANGUAGE: [Nivel de lenguaje técnico]
GOAL: [Meta específica]
PROCESS: [Proceso o pasos a seguir]
TONE: [Tono de la respuesta]
```

**Cuándo usarlo:**

- Comunicación con audiencias específicas
- Documentación técnica
- Presentaciones académicas
- Adaptación de contenido

**Ejemplo aplicado a Divulgación Científica:**

```
LANGUAGE: Lenguaje simple, sin tecnicismos, como para estudiantes de secundaria
GOAL: Explicar qué es el cambio climático y sus efectos en Perú
PROCESS: 1) Definición básica, 2) Causas principales, 3) Efectos en glaciares peruanos, 4) Acciones individuales
TONE: Educativo pero optimista, motivando a la acción
```

**Ejemplo aplicado a Investigación Académica:**

```
LANGUAGE: Académico formal, con terminología especializada de economía
GOAL: Analizar el impacto de la pandemia COVID-19 en la economía informal peruana
PROCESS: 1) Marco teórico, 2) Análisis de datos pre/post pandemia, 3) Comparación sectorial, 4) Proyecciones
TONE: Objetivo, analítico, basado en evidencia
```

#### 2. Framework 6: SCOPE (Situation-Complication-Objective-Plan-Evaluation)

**Estructura:**

```
SITUATION: [Situación actual]
COMPLICATION: [Problema o desafío]
OBJECTIVE: [Objetivo a lograr]
PLAN: [Plan de acción]
EVALUATION: [Criterios de éxito]
```

**Cuándo usarlo:**

- Resolución de problemas complejos
- Planificación de proyectos
- Propuestas de investigación
- Análisis de casos

**Ejemplo aplicado a Ingeniería Ambiental:**

```
SITUATION: La ciudad de Ayacucho genera 150 toneladas de residuos sólidos diarios
COMPLICATION: Solo el 40% se gestiona adecuadamente, causando contaminación de ríos
OBJECTIVE: Diseñar un sistema de gestión de residuos que aumente a 80% la gestión adecuada
PLAN: Proponer 5 estrategias viables con costos, tecnología y participación comunitaria
EVALUATION: Evaluar cada estrategia según: costo, viabilidad técnica, impacto ambiental, aceptación social
```

**Ejemplo aplicado a Educación:**

```
SITUATION: Estudiantes universitarios muestran bajo rendimiento en cursos de estadística
COMPLICATION: 60% reprueba el curso en el primer intento, causando retraso académico
OBJECTIVE: Desarrollar metodología de enseñanza que reduzca la tasa de reprobación a 30%
PLAN: Diseñar intervención educativa con 4 componentes (tecnología, tutorías, evaluación, motivación)
EVALUATION: Definir indicadores medibles de éxito en un semestre piloto
```

#### 3. Framework 7: TRACE (Task-Request-Action-Context-Example)

**Estructura:**

```
TASK: [Tarea general]
REQUEST: [Solicitud específica]
ACTION: [Acción concreta a realizar]
CONTEXT: [Contexto relevante]
EXAMPLE: [Ejemplo del tipo de salida esperada]
```

**Cuándo usarlo:**

- Cuando necesitas un formato muy específico
- Generación de contenido estructurado
- Respuestas que requieren ejemplos claros
- Tareas repetitivas con variaciones

**Ejemplo aplicado a Redacción Académica:**

```
TASK: Redactar abstracts de investigación
REQUEST: Genera un abstract para mi investigación sobre desnutrición infantil en Ayacucho
ACTION: Escribe un abstract de 250 palabras siguiendo estructura IMRAD (Introducción, Métodos, Resultados, Discusión)
CONTEXT: Estudio cuantitativo con 500 niños menores de 5 años, datos de centros de salud 2023-2024
EXAMPLE: [Introducción: 2-3 oraciones sobre el problema], [Métodos: 2-3 oraciones sobre diseño y muestra], [Resultados: 3-4 oraciones con hallazgos principales], [Discusión: 2-3 oraciones sobre implicaciones]
```

**Ejemplo aplicado a Análisis de Datos:**

```
TASK: Interpretar resultados estadísticos
REQUEST: Explica estos resultados de correlación de Pearson para mi tesis
ACTION: Interpreta r=0.73, p<0.001 entre nivel educativo materno y estado nutricional infantil
CONTEXT: Investigación en zona rural de Ayacucho, n=500, variables medidas en escala ordinal y continua
EXAMPLE: "Se encontró una correlación [positiva/negativa] [débil/moderada/fuerte] estadísticamente significativa (r=X, p=Y) entre [variable 1] y [variable 2], lo que sugiere que [interpretación práctica]..."
```

#### 4. Framework 8: SPAR (Situation-Problem-Action-Result)

**Estructura:**

```
SITUATION: [Situación o contexto]
PROBLEM: [Problema específico]
ACTION: [Acción propuesta]
RESULT: [Resultado esperado]
```

**Cuándo usarlo:**

- Estudios de caso
- Simulaciones de escenarios
- Propuestas de solución
- Análisis de intervenciones

**Ejemplo aplicado a Salud Pública:**

```
SITUATION: Hospital regional de Ayacucho tiene alta tasa de infecciones intrahospitalarias
PROBLEM: 15% de pacientes hospitalizados desarrollan infecciones, duplicando el promedio nacional
```

#### 2. Framework 10: COAST (Context-Objective-Actions-Scenario-Task)

**Estructura:**

```
CONTEXT: [Contexto amplio de la situación]
OBJECTIVE: [Objetivo principal a lograr]
ACTIONS: [Acciones previas o información disponible]
SCENARIO: [Escenario específico o restricciones]
TASK: [Tarea concreta solicitada]
```

**Cuándo usarlo:**

- Proyectos complejos con múltiples variables
- Planificación estratégica detallada
- Situaciones con restricciones específicas
- Propuestas multifacéticas

**Ejemplo aplicado a Proyectos de Desarrollo:**

```
CONTEXT: Soy parte de un equipo que trabaja con comunidades rurales en la provincia de Huanta, Ayacucho, para mejorar la seguridad alimentaria.

OBJECTIVE: Diseñar un programa sostenible de huertos familiares que aumente la disponibilidad de vegetales nutritivos en 50 familias durante todo el año.

ACTIONS: Ya identificamos 5 comunidades interesadas, realizamos diagnóstico de suelos, y tenemos compromiso de apoyo del gobierno local. Presupuesto disponible: S/. 80,000 para primer año.

SCENARIO: Clima andino con heladas 4 meses al año, escasez de agua, alta migración de jóvenes, lengua predominante quechua, bajo nivel de alfabetización formal pero amplio conocimiento agrícola tradicional.

TASK: Desarrolla un plan de implementación detallado en 5 fases que integre: 1) capacitación intercultural, 2) infraestructura adaptada al clima, 3) selección de cultivos resistentes, 4) sistema de riego eficiente, 5) estrategia de sostenibilidad post-proyecto. Incluye cronograma, presupuesto distribuido, indicadores de éxito, y plan de mitigación de riesgos.
```

**Ejemplo aplicado a Diseño de Currículo:**

```
CONTEXT: La Facultad de Ingeniería de Sistemas de mi universidad necesita actualizar su plan de estudios para incluir temas de inteligencia artificial y ciencia de datos.

OBJECTIVE: Diseñar 3 nuevos cursos electivos de nivel intermedio que preparen a los estudiantes para trabajar con IA en el contexto peruano.

ACTIONS: Se aprobó la creación de cursos electivos de 4 créditos cada uno, con 16 semanas de duración. Los prerrequisitos son: programación en Python, estadística básica, y estructuras de datos.

```

#### 3. Framework 11: RACE (Role-Action-Context-Expectation)

**Estructura:**

```
ROLE: [Rol específico y detallado de la IA]
ACTION: [Acción principal solicitada]
CONTEXT: [Contexto relevante]
EXPECTATION: [Expectativas específicas del resultado]
```

**Cuándo usarlo:**

- Simulaciones de roles profesionales
- Asesoramiento especializado
- Revisión de trabajos académicos
- Feedback constructivo

**Ejemplo aplicado a Revisión de Propuestas:**

```
ROLE: Actúa como un evaluador experto de proyectos de investigación en ciencias sociales, con experiencia en metodología cualitativa y conocimiento profundo del contexto sociocultural de la región andina peruana.

ACTION: Revisa críticamente esta propuesta de investigación sobre prácticas de crianza infantil en comunidades quechuas de Ayacucho, evaluando rigurosidad metodológica, pertinencia cultural, y viabilidad ética.

CONTEXT: La propuesta busca financiamiento de una convocatoria universitaria para tesis de licenciatura. El presupuesto máximo es S/. 15,000 y el plazo de ejecución es 8 meses. El investigador es estudiante de Antropología sin experiencia previa en trabajo de campo pero con conocimiento básico del quechua.

EXPECTATION: Proporciona feedback estructurado en 5 secciones: 1) Fortalezas de la propuesta (3-4 puntos), 2) Debilidades metodológicas identificadas (3-4 puntos), 3) Sugerencias específicas de mejora con ejemplos concretos, 4) Evaluación de viabilidad (escala 1-10 con justificación), 5) Recomendaciones bibliográficas de al menos 5 fuentes clave sobre el tema.
```

**Ejemplo aplicado a Análisis de Textos:**

```
ROLE: Eres un analista de discurso especializado en comunicación política y medios, con expertise en análisis crítico de narrativas mediáticas en contextos latinoamericanos.

ACTION: Analiza estos 3 artículos periodísticos sobre el mismo evento político en Perú, identificando marcos interpretativos (framing), sesgos editoriales, y estrategias retóricas empleadas por cada medio.

CONTEXT: Los artículos son de 3 medios con líneas editoriales diferentes: uno de centro-izquierda, uno conservador, y uno considerado "independiente". El evento analizado es una protesta social reciente en Ayacucho. Tu análisis será usado como ejemplo metodológico en mi tesis sobre representación mediática de movimientos sociales regionales.

EXPECTATION: Produce un análisis comparativo estructurado que incluya: 1) Tabla comparativa de marcos interpretativos dominantes en cada artículo, 2) Identificación de fuentes citadas y su posicionamiento, 3) Análisis de vocabulario y términos clave usados ("protesta" vs. "disturbio" vs. "movilización"), 4) Interpretación de qué narrativa subyacente promueve cada medio, 5) Reflexión metodológica sobre cómo este tipo de análisis puede aplicarse sistemáticamente en investigación académica.
```

#### 4. Framework 12: RISE (Role-Input-Steps-Expectation)

**Estructura:**

```
ROLE: [Rol específico de la IA]
INPUT: [Información o datos de entrada]
STEPS: [Pasos o proceso a seguir]
EXPECTATION: [Resultado esperado con detalles]
```

**Cuándo usarlo:**

- Procesos paso a paso
- Transformación de datos
- Tutoriales y guías
- Análisis estructurados

**Ejemplo aplicado a Análisis de Datos:**

```
ROLE: Actúa como un estadístico experto en análisis de encuestas y especialista en software R para análisis de datos sociales.

INPUT: Tengo un archivo CSV con 400 respuestas de una encuesta sobre acceso a servicios de salud en zonas rurales de Ayacucho. Las variables son: distrito (categórica, 10 distritos), edad (continua), sexo (binaria), tiempo de viaje al centro de salud (continua en minutos), frecuencia de visitas (ordinal: nunca, rara vez, a veces, frecuentemente), satisfacción con servicio (escala Likert 1-5), y tipo de seguro (categórica: SIS, EsSalud, privado, ninguno).

STEPS: Guíame paso a paso en R para: 1) Cargar y explorar los datos, 2) Limpiar datos (valores perdidos, outliers), 3) Crear visualizaciones descriptivas de cada variable, 4) Realizar análisis bivariado entre tiempo de viaje y frecuencia de visitas, 5) Probar si hay diferencias en satisfacción según tipo de seguro (ANOVA o Kruskal-Wallis según corresponda), 6) Crear un informe básico con resultados.

EXPECTATION: Proporciona código R completo y comentado para cada paso, explica qué hace cada línea de código, incluye interpretación de outputs clave, recomienda paquetes específicos (tidyverse, ggplot2, etc.), y al final genera un script reproducible completo que pueda ejecutar de principio a fin para replicar todo el análisis.
```

**Ejemplo aplicado a Desarrollo de Contenidos:**

```
ROLE: Eres un diseñador instruccional especializado en educación superior y experto en creación de materiales educativos con enfoque constructivista.

INPUT: Necesito crear material didáctico para enseñar el concepto de "elasticidad precio de la demanda" en un curso de microeconomía para estudiantes de primer año de Economía.

STEPS: Desarrolla una guía paso a paso para crear una clase de 2 horas que incluya: 1) Actividad de apertura para activar conocimientos previos (15 min), 2) Explicación conceptual con ejemplos del contexto peruano (30 min), 3) Ejercicio práctico grupal calculando elasticidades con datos reales (40 min), 4) Discusión plenaria sobre implicaciones para políticas públicas (20 min), 5) Evaluación formativa y cierre (15 min).

EXPECTATION: Para cada paso, proporciona: objetivos de aprendizaje específicos, descripción detallada de la actividad con instrucciones para el docente, materiales necesarios (datasets, presentaciones, hojas de trabajo), ejemplos específicos usando productos/servicios peruanos (ej: transporte público, papa, quinua), preguntas clave para guiar discusiones, y criterios de evaluación formativa. Incluye también sugerencias de adaptación para modalidad virtual sincrónica.
```


**Cuándo usarlo:**

**Ejemplo aplicado a Planificación de Investigación:**

```
SITUATION: Tengo aprobada mi propuesta de tesis sobre "Impacto de programas de alfabetización digital en adultos mayores de Ayacucho", pero necesito diseñar el plan de trabajo para los próximos 6 meses antes de comenzar el trabajo de campo.

EXPECTATION: Un diagrama de Gantt o cronograma semanal que especifique: actividades concretas por semana, hitos verificables, recursos necesarios en cada fase, posibles riesgos y planes de contingencia, y puntos de revisión con mi asesor. Formato: tabla o lista estructurada compatible con herramientas de gestión de proyectos.
```

**Ejemplo aplicado a Desarrollo de Producto/Servicio:**

```
SITUATION: Como parte de mi proyecto final de Ingeniería de Sistemas, debo desarrollar una aplicación móvil para pequeños comerciantes del mercado central de Ayacucho que facilite la gestión de inventarios y ventas. Actualmente, estos comerciantes llevan registro manual en cuadernos, lo que genera pérdidas por mal control de stock.

ACTION: Diseña la arquitectura técnica y funcional de esta aplicación, definiendo: tecnologías a usar (frontend, backend, base de datos), módulos principales, flujo de usuario, y estrategia de implementación.

GOAL: Lanzar MVP (Producto Mínimo Viable) funcional en 3 meses, que al menos 10 comerciantes puedan usar diariamente para registrar ventas y consultar inventario desde sus smartphones.

EXPECTATION: Documento técnico de diseño que incluya: 1) Stack tecnológico justificado (considerando que debe ser gratuito/open source y funcionar offline), 2) Diagrama de arquitectura, 3) Mockups básicos de 5 pantallas principales, 4) Plan de desarrollo en sprints de 2 semanas, 5) Estrategia de pruebas con usuarios reales, 6) Consideraciones de usabilidad para usuarios con bajo nivel de alfabetización digital.
```

#### 2. Framework 14: TAG (Task-Action-Goal)

**Estructura:**

```
TASK: [Tarea específica]
ACTION: [Acción concreta a realizar]
GOAL: [Objetivo o propósito]
```

**Cuándo usarlo:**

- Tareas directas y específicas
- Cuando el contexto es obvio
- Comunicación rápida y eficiente
- Prompts concisos pero efectivos

**Ejemplo aplicado a Redacción Académica:**

```
TASK: Redactar la sección de "Justificación" para mi monografía sobre conservación de patrimonio arqueológico en la región de Ayacucho.

ACTION: Escribe 3 párrafos que argumenten: 1) relevancia académica del tema, 2) relevancia social y cultural para la región, 3) vacío en la literatura que esta investigación aborda.

GOAL: Convencer al lector (comité académico) de que esta investigación es necesaria, oportuna y puede generar aportes significativos tanto teóricos como prácticos para la preservación del patrimonio cultural de Ayacucho.
```

**Ejemplo aplicado a Análisis de Datos:**

```
TASK: Interpretar los resultados de mi análisis de regresión múltiple sobre factores que predicen el rendimiento académico universitario.

ACTION: Analiza esta tabla de coeficientes de regresión: Variable1 (horas de estudio) β=0.42, p<0.001; Variable2 (asistencia a clases) β=0.31, p=0.003; Variable3 (nivel socioeconómico) β=0.18, p=0.045; R²=0.67.

GOAL: Escribir la interpretación de resultados para la sección de "Resultados" de mi tesis, explicando qué significa cada coeficiente, cuál variable tiene mayor efecto, y qué implica el R² encontrado, en lenguaje académico pero comprensible.
```

#### 3. Framework 15: CRISPE (Capacity-Role-Insight-Statement-Personality-Experiment)

**Estructura:**

```
CAPACITY: [Capacidad o competencia requerida]
ROLE: [Rol específico de la IA]
INSIGHT: [Perspectiva o enfoque deseado]
STATEMENT: [Declaración o premisa de trabajo]
PERSONALITY: [Tono y estilo de comunicación]
EXPERIMENT: [Espacio para experimentación o creatividad]
```

**Cuándo usarlo:**

- Tareas creativas y exploratoria
- Cuando necesitas un tono muy específico
- Generación de contenido original
- Proyectos innovadores o no convencionales

**Ejemplo aplicado a Comunicación Científica:**

```
CAPACITY: Necesito habilidades de divulgación científica para comunicar investigación compleja a público general.

ROLE: Actúa como un comunicador científico especializado en hacer accesibles temas de salud pública para audiencias rurales con educación primaria.

INSIGHT: Adopta un enfoque narrativo que use historias locales, metáforas culturalmente relevantes, y ejemplos cotidianos del contexto andino peruano.

STATEMENT: Mi investigación demuestra que la anemia infantil en comunidades rurales de Ayacucho está relacionada no solo con deficiencia de hierro, sino con prácticas alimentarias tradicionales que limitan la absorción de nutrientes.

PERSONALITY: Tono cálido, empático, respetuoso de la cultura local, sin ser condescendiente. Evita tecnicismos médicos y usa lenguaje sencillo. Transmite urgencia pero también empoderamiento.

EXPERIMENT: Crea 3 versiones diferentes de un mensaje de salud pública (300 palabras cada una) dirigido a madres de familia en comunidades quechuas, que explique cómo mejorar la alimentación infantil integrando conocimientos tradicionales con evidencia científica. Experimenta con: 1) formato de historia/testimonio, 2) formato de consejos prácticos paso a paso, 3) formato de preguntas y respuestas comunes.
```

**Ejemplo aplicado a Propuesta de Innovación:**

```
CAPACITY: Requiero pensamiento de diseño (design thinking) para innovación social en contextos de recursos limitados.

ROLE: Eres un consultor en innovación social con experiencia en proyectos comunitarios en zonas rurales de América Latina, especializado en soluciones de bajo costo y alta sostenibilidad.

INSIGHT: Enfócate en soluciones que aprovechen recursos locales existentes, fortalezcan vínculos comunitarios, y sean replicables sin dependencia de tecnología compleja o financiamiento externo continuo.

STATEMENT: Las comunidades rurales de Ayacucho tienen alto potencial turístico debido a su patrimonio arqueológico y cultural, pero carecen de capacidades empresariales y acceso a mercados para desarrollar emprendimientos turísticos sostenibles.

PERSONALITY: Inspirador pero pragmático. Optimista sobre el potencial local sin ser ingenuo sobre los desafíos. Usa lenguaje motivador que empodere a las comunidades como protagonistas de su desarrollo.

EXPERIMENT: Propón 3 modelos de negocio innovadores para turismo comunitario que: 1) no requieran inversión inicial mayor a S/. 10,000, 2) generen ingresos distribuidos equitativamente, 3) preserven la autenticidad cultural, 4) sean liderados por mujeres y jóvenes locales. Para cada modelo, describe: propuesta de valor, estructura organizativa, fuentes de ingreso, sostenibilidad a 3 años. Sé creativo pero realista.
```

#### 4. Framework 16: SMART (Specific-Measurable-Achievable-Relevant-Time-bound)

**Estructura:**

```
SPECIFIC: [Objetivo específico y claro]
MEASURABLE: [Criterios medibles de éxito]
ACHIEVABLE: [Recursos y capacidades disponibles]
RELEVANT: [Relevancia y justificación]
TIME-BOUND: [Marco temporal definido]
```

**Cuándo usarlo:**

- Definición de objetivos de investigación
- Planificación de proyectos
- Establecimiento de metas académicas
- Evaluación de viabilidad

**Ejemplo aplicado a Objetivos de Investigación:**

```
SPECIFIC: Evaluar el impacto del programa "Aprende Saludable" del MINSA en la reducción de anemia infantil en niños de 6-36 meses en el distrito de San Juan Bautista, Ayacucho.

MEASURABLE: Comparar niveles de hemoglobina en sangre antes y después de 6 meses de intervención, esperando reducción de prevalencia de anemia de 45% a menos de 30%. Medir también adherencia al programa (% de madres que asisten a controles mensuales) y cambios en prácticas alimentarias (mediante encuesta estructurada).

ACHIEVABLE: Tengo acceso a datos del centro de salud local con autorización del MINSA regional. Puedo trabajar con una muestra de 120 niños (grupo intervención) y 80 niños (grupo control). Cuento con apoyo de 2 enfermeras del centro de salud. Presupuesto de S/. 3,000 para materiales y transporte.

RELEVANT: La anemia infantil es el principal problema de salud pública en Ayacucho (una de las regiones con mayor prevalencia en Perú). Evaluar efectividad de programas gubernamentales es crucial para políticas públicas basadas en evidencia. Mi investigación puede informar recomendaciones para escalar el programa.

TIME-BOUND: Duración total del estudio: 8 meses (1 mes preparación, 6 meses seguimiento, 1 mes análisis). Recolección de datos: enero-julio 2026. Análisis y redacción: agosto 2026. Defensa de tesis: septiembre 2026.

---

TAREA PARA LA IA: Basándote en estos componentes SMART, genera:
1. Una matriz de operacionalización de variables (tabla con: variable, definición conceptual, definición operacional, indicadores, instrumento de medición)
2. Un cronograma detallado semana por semana para los 8 meses
3. Lista de posibles riesgos y planes de mitigación
4. Presupuesto detallado de los S/. 3,000 (distribuidos en categorías: transporte, materiales, reactivos, otros)
```

**Ejemplo aplicado a Metas Académicas:**

```
SPECIFIC: Desarrollar competencias avanzadas en análisis de datos cualitativos usando software ATLAS.ti y NVivo para mi tesis de investigación cualitativa sobre identidad cultural en jóvenes quechuas urbanos de Ayacucho.

MEASURABLE: Al finalizar 2 meses, ser capaz de: 1) codificar 30 entrevistas semi-estructuradas, 2) crear al menos 50 códigos temáticos organizados jerárquicamente, 3) generar mapas conceptuales de relaciones entre temas, 4) extraer citas representativas para cada categoría, 5) redactar hallazgos preliminares basados en el análisis.

TIME-BOUND: Semana 1-2: tutoriales básicos y familiarización. Semana 3-4: práctica con dataset de ejemplo. Semana 5-6: codificación de primeras 15 entrevistas. Semana 7-8: completar 30 entrevistas y generar análisis preliminar. Meta final: 30 de marzo de 2026.

TAREA PARA LA IA: Crea un plan de aprendizaje detallado que incluya:

```

#### 1. ¿Por qué Obsidian? Filosofía del "Second Brain"

**Concepto de Second Brain:**

- **Problema:** Nuestra memoria es limitada y poco confiable
- **Solución:** Externalizar conocimiento en un sistema digital organizado
- **Beneficio:** Liberar mente para pensar, no para recordar

**Principios del Second Brain:**

1. **Capturar:** Guardar todo lo relevante
2. **Organizar:** Conectar ideas de forma significativa
3. **Destilar:** Extraer la esencia de la información
4. **Expresar:** Usar el conocimiento para crear

**¿Por qué Obsidian específicamente?**

|Característica|Beneficio|
|---|---|
|Archivos en Markdown (.md)|Tus datos son tuyos, no dependen de una empresa|
|Almacenamiento local|Privacidad total, funciona offline|
|Enlaces bidireccionales|Crear red de conocimiento interconectado|
|Grafo de conocimiento|Visualizar relaciones entre ideas|
|Plugins comunitarios|Extender funcionalidad infinitamente|
|Gratis y multiplataforma|Windows, Mac, Linux, iOS, Android|

**Comparación con otras herramientas:**

|Herramienta|Ventajas|Desventajas para académicos|
|---|---|---|
|Notion|Colaboración, bases de datos|Propietario, requiere internet, exportación limitada|
|Evernote|Simple, OCR potente|Costo, formato propietario|
|OneNote|Integrado con Microsoft|No usa Markdown, difícil exportar|
|**Obsidian**|Software libre, Markdown, local|Curva de aprendizaje inicial|

#### 3. Markdown Esencial

**¿Qué es Markdown?**

- Lenguaje de marcado ligero
- Se escribe en texto plano
- Se visualiza con formato
- Universal (funciona en cualquier editor)

**Sintaxis básica:**

**Headers (Títulos):**

```markdown
# Título 1 (más grande)
## Título 2
### Título 3
#### Título 4
##### Título 5
###### Título 6 (más pequeño)
```

**Énfasis:**

```markdown
*cursiva* o _cursiva_
**negrita** o __negrita__
***negrita y cursiva*** o ___negrita y cursiva___
~~tachado~~
==resaltado== (específico de Obsidian)
```

**Listas ordenadas:**

```markdown
1. Primer elemento
2. Segundo elemento
3. Tercer elemento
   4. Sub-elemento (indentar con 3 espacios o 1 tab)
   5. Otro sub-elemento
6. Cuarto elemento
```

**Listas no ordenadas:**

```markdown
- Elemento con guion
- Otro elemento
  - Sub-elemento
  - Otro sub-elemento
- Tercer elemento

* También funciona con asterisco
+ O con signo más
```

**Enlaces externos:**

```markdown
[Texto del enlace](https://www.ejemplo.com)

Ejemplo:
[Universidad de Huamanga](https://www.unsch.edu.pe)
```

**Imágenes:**

```markdown
![Texto alternativo](ruta/a/imagen.png)

Ejemplo:
![Logo UNSCH](Attachments/logo-unsch.png)
```

**Enlaces internos (específico de Obsidian):**

```markdown
[[Nombre de otra nota]]

Para enlazar a sección específica:
[[Nombre de nota#Sección]]

Para enlazar con texto diferente:
[[Nombre de nota|Texto que se muestra]]

Ejemplo:
Ver más en [[Marco Teórico]]
```

**Bloques de código:**

Código inline:

```markdown
Usa el comando `print()` en Python.
```

Bloque de código:

````markdown
```python
def suma(a, b):
    return a + b

resultado = suma(5, 3)
print(resultado)
```
````

**Notas importantes:**

- Los 3 backticks (```) abren y cierran bloque
- Especificar lenguaje después de primeros ``` para syntax highlighting

#### 2. Sistema Zettelkasten

**¿Qué es Zettelkasten?**

- Sistema de notas desarrollado por Niklas Luhmann (sociólogo alemán)
- Escribió 70 libros y 400 artículos usando este método
- "Zettelkasten" = "Caja de notas" en alemán

**Principios fundamentales:**

**1. Atomicidad:**

- Una nota = Una idea
- Título descriptivo y específico
- Autosuficiente (se entiende sin contexto)

```markdown
# ❌ MAL: Nota muy general
# Teorías de aprendizaje

# ✅ BIEN: Nota atómica
# Constructivismo - El conocimiento se construye activamente
```

**2. Conexión sobre categorización:**

- Importancia de ENLACES sobre carpetas
- Una nota puede conectarse con muchas otras
- Red de conocimiento vs. jerarquía rígida

**3. Enlaces bidireccionales:**

```markdown
# Nota: Anemia infantil en Ayacucho

La [[deficiencia de hierro]] es la principal causa de 
[[anemia]] en niños menores de 5 años en zonas rurales 
de [[Ayacucho]].

Esta condición está relacionada con [[prácticas alimentarias]]
y [[acceso a servicios de salud]].

# Referencias cruzadas
Ver también: [[Desnutrición crónica]], [[Programas sociales MINSA]]
```

**Cuando haces clic en "deficiencia de hierro", Obsidian:**

- Abre esa nota si existe
- Te permite crearla si no existe
- Muestra backlinks (qué otras notas enlazan a esta)

**4. Tags (Etiquetas):**

```markdown
# Uso de tags para categorización flexible

#concepto #economía #microeconomía 
#paper #metodología #cualitativo
#monografía #marco-teórico
#autor/Marx #año/1867

# Puedes usar tags anidados
#metodología/cualitativa/entrevistas
#metodología/cuantitativa/encuestas
```

**Mejores prácticas para tags:**

- Usa guiones en lugar de espacios: `#marco-teórico`
- Sé consistente con mayúsculas/minúsculas
- No abuses de tags - máximo 5 por nota
- Crea sistema de tags antes de empezar

**5. Grafo de conocimiento:**

- Visualización de red de notas
- Identifica clusters de ideas relacionadas
- Descubre conexiones inesperadas

**6. Flujo de trabajo Zettelkasten:**

```
1. CAPTURAR → Inbox
   - Anota idea rápidamente
   - Sin preocuparte por formato perfecto

2. PROCESAR → Convertir en nota atómica
   - Reformula en tus palabras
   - Añade contexto necesario
   - Título descriptivo

3. CONECTAR → Agregar enlaces
   - ¿A qué notas existentes se relaciona?
   - ¿Contradice o apoya otras ideas?
   - Añadir tags relevantes

4. CREAR → Usar notas para producir
   - Combinar notas para escribir
   - Las conexiones revelan insights
   - De notas a monografía
```

```markdown
# Elasticidad precio de la demanda - Definición

## Concepto
La elasticidad precio de la demanda mide la sensibilidad de la 
cantidad demandada de un bien ante cambios en su precio. Se calcula 
como el porcentaje de cambio en cantidad demandada dividido por el 
porcentaje de cambio en precio.

## Fórmula
$$
E_d = \frac{\% \Delta Q_d}{\% \Delta P}
$$

## Interpretación
- $|E_d| > 1$: Demanda elástica (sensible al precio)
- $|E_d| < 1$: Demanda inelástica (poco sensible)
- $|E_d| = 1$: Demanda unitaria

## Ejemplo contexto peruano
El transporte público en Ayacucho tiene demanda relativamente 
inelástica porque hay pocas alternativas. Un aumento del 20% en 
tarifas podría reducir demanda solo en 8% (E_d ≈ -0.4).

## Conexiones
- Relacionado con [[Ley de demanda]]
- Determina [[Incidencia tributaria]]
- Contrasta con [[Elasticidad ingreso]]
- Aplicación en [[Política de precios]]

## Tags
#microeconomía #concepto #elasticidad

## Fuente
- Mankiw, N. G. (2020). Principios de Economía. Cap. 5
- Notas de clase: Microeconomía I
```

#### 2. Scite - Verificación de Citas

**¿Qué es Scite?**

- Plataforma que analiza CÓMO los papers citan a otros
- Clasifica citas como: Supporting, Contrasting, Mentioning
- Ayuda a verificar consenso científico

**Acceso:**

- https://scite.ai
- Versión gratuita: Limitada (10 búsquedas/mes)
- Versión estudiante: Descuento disponible
- Alternativa: Usar extensión de navegador

**Conceptos clave:**

**Smart Citations:**

```
Cuando Paper B cita a Paper A, Scite clasifica:

🟢 SUPPORTING (Apoya)
"Estos resultados confirman los hallazgos de Smith et al. (2020)..."

🔴 CONTRASTING (Contradice)
"Contrario a lo reportado por López (2019), nuestros datos muestran..."

⚪ MENTIONING (Solo menciona)
"Varios estudios (García, 2018; Pérez, 2020) han abordado este tema..."
```

**Scite Index:**

- Número que indica confiabilidad de un paper
- Basado en citas supporting vs. contrasting
- Ayuda a identificar papers controversiales

**Cómo usar Scite:**

**1. Verificar confiabilidad de un paper:**

```
Caso: Encontraste un paper que parece perfecto para tu monografía

Proceso:
1. Ir a Scite.ai
2. Buscar por DOI o título del paper
3. Ver "Citation Statements"
   - ¿Cuántas citas supporting tiene?
   - ¿Hay citas contrasting? ¿Por qué razones?

Interpretación:
- 20 supporting, 2 contrasting → Probablemente confiable
- 5 supporting, 15 contrasting → Hallazgos controversiales
- 0 citas → Paper muy reciente o poco influyente
```

**2. Encontrar papers que confirman/contradicen una idea:**

```
Pregunta de investigación: 
"¿La suplementación con hierro reduce anemia infantil?"

En Scite:
1. Buscar paper clave sobre el tema
2. Ver "Supporting citations" 
   → Papers que confirman efectividad
3. Ver "Contrasting citations" 
   → Papers que cuestionan efectividad

Resultado: Panorama equilibrado del debate científico
```

**3. Rastrear desarrollo de una idea:**

```
Concepto: "Determinantes sociales de la salud"

1. Buscar paper seminal (ej: Marmot, 2005)
2. Ver citas a través del tiempo
3. Identificar cómo evolucionó el concepto
4. Encontrar aplicaciones recientes al contexto latinoamericano
```

**Script para procesar múltiples páginas:**

```python
import pytesseract
from PIL import Image
import os

# Carpeta con imágenes escaneadas
carpeta_input = 'scans/'
archivo_output = 'documento-completo.txt'

# Procesar todas las imágenes
texto_completo = ""

for archivo in sorted(os.listdir(carpeta_input)):
    if archivo.endswith(('.jpg', '.png', '.tiff')):
        ruta = os.path.join(carpeta_input, archivo)
        img = Image.open(ruta)
        texto = pytesseract.image_to_string(img, lang='spa')
        texto_completo += f"\n\n--- {archivo} ---\n\n{texto}"
        print(f"Procesado: {archivo}")

# Guardar todo junto
with open(archivo_output, 'w', encoding='utf-8') as f:
    f.write(texto_completo)

print(f"Documento completo guardado en {archivo_output}")
```

**Ventajas de Tesseract:**

- Integrable en flujos de trabajo complejos

**Desventajas:**

- Requiere conocimientos de Python
- Configuración inicial más compleja
- Calidad depende mucho de imagen original

#### 1. Filosofía del Software Libre Aplicado a Investigación

**¿Por qué software libre en investigación académica?**

**Principios fundamentales:**

```
1. LIBERTAD

5. SOSTENIBILIDAD

   - Financiado por fundaciones, no por capital de riesgo
```

#### 3. Conceptos Básicos de Zotero

**Biblioteca Personal (My Library)**

```
Estructura jerárquica:

My Library
├── Colecciones (como carpetas)
│   ├── Colección 1
│   │   ├── Subcolección 1.1
│   │   └── Subcolección 1.2
│   ├── Colección 2
│   └── Colección 3
├── Items (elementos bibliográficos)
│   ├── Artículo de revista
│   ├── Libro
│   ├── Tesis
│   └── Página web
└── Adjuntos (PDFs, imágenes, etc.)
```

**Biblioteca vs. Colecciones:**

```
BIBLIOTECA = Toda tu base de datos
COLECCIONES = Organizadores (no duplican items)

Ejemplo:
Paper "Smith 2020" está en:
- Colección "Marco Teórico"
- Colección "Metodología Cualitativa"
- Colección "Monografía 2026"

Pero existe UNA SOLA VEZ en la biblioteca
(Las colecciones son solo "etiquetas virtuales")
```

**Items (Elementos bibliográficos)**

**Tipos de items principales:**

```
📄 Journal Article (Artículo de revista)
   - Autor(es)
   - Título del artículo
   - Revista
   - Volumen, Número, Páginas
   - Año
   - DOI
   - ISSN

📚 Book (Libro)
   - Autor(es) / Editor(es)
   - Título
   - Editorial
   - Lugar de publicación
   - Año
   - ISBN
   - Número de páginas

📖 Book Section (Capítulo de libro)
   - Autor del capítulo
   - Título del capítulo
   - Editor del libro
   - Título del libro
   - Páginas del capítulo
   - Editorial, año

🎓 Thesis (Tesis)
   - Autor
   - Título
   - Tipo (Licenciatura, Maestría, Doctorado)
   - Universidad
   - Lugar
   - Año

🌐 Web Page (Página web)
   - Autor (si hay)
   - Título de la página
   - Sitio web
   - URL
   - Fecha de acceso

📰 Newspaper Article (Artículo periodístico)
   - Autor
   - Título
   - Periódico
   - Fecha
   - Páginas

🎥 Film / Video
   - Director
   - Título
   - Estudio/Distribuidor
   - Fecha
   - Duración

📊 Report (Informe)
   - Autor(es)
   - Título
   - Institución
   - Número de informe
   - Lugar
   - Fecha

📝 Document (Documento genérico)
   - Para tipos no especificados
```

**Metadatos:**

```
Metadatos = Información SOBRE el documento

Metadatos esenciales:
✅ Autor(es)
✅ Título
✅ Año de publicación
✅ Fuente (revista, editorial, etc.)

Metadatos opcionales pero importantes:
⚪ DOI (Digital Object Identifier)
⚪ Abstract/Resumen
⚪ Keywords/Palabras clave
⚪ URL
⚪ ISSN / ISBN
⚪ Número de páginas

Metadatos adicionales útiles:
⚪ Fecha de acceso (para web)
⚪ Volumen y número (revistas)
⚪ Edición (libros)
⚪ Traductor (traducciones)
```

**Adjuntos (Attachments):**

```
Tipos de adjuntos:

📎 PDF (más común)
   - Paper completo
   - Capítulo de libro escaneado
   - Tesis

📎 HTML Snapshot
   - Copia de página web completa
   - Se guarda localmente

📎 Imágenes
   - Figuras de papers
   - Infografías
   - Capturas de pantalla

📎 Notas
   - Anotaciones personales
   - Resúmenes
   - Ideas

Cada item puede tener MÚLTIPLES adjuntos
```

**Tipos de adjuntos y su uso:**

```
1. PDF - Artículo completo

   ├─ Datasets, tablas extendidas, figuras adicionales

   └─ Uso: Análisis profundo, replicación

   ├─ Copia completa de página web
   ├─ Incluye imágenes, CSS, JS (estático)

   └─ Citas destacadas
```

#### 2. Métodos Avanzados de Captura

**Añadir fuentes usando DOI o ISBN directamente**

**Usando DOI (Digital Object Identifier):**

```
¿Qué es el DOI?
- Identificador único y permanente de documentos académicos
- Formato: 10.XXXX/YYYYYYYY
- Persiste incluso si URL cambia
- Ej: 10.1371/journal.pone.0245678

Cómo añadir por DOI en Zotero:

1. Click en varita mágica (🪄) "Add Item(s) by Identifier"

2. Pegar DOI (sin "https://doi.org/", solo el número):
   10.17843/rpmesp.2017.344.2975

3. Enter

4. Zotero:
   - Consulta CrossRef, DataCite, y otras bases
   - Recupera metadatos completos
   - Intenta descargar PDF (si hay acceso abierto)
   - Crea item automáticamente

5. Verificar metadatos (generalmente son 100% precisos)

Ventajas:
✅ Metadatos extremadamente precisos
✅ Rápido (segundos)
✅ No requiere visitar sitio web
✅ Funciona con mayoría de papers recientes (post-2000)

Dónde encontrar DOI:
- Primera página del paper (generalmente esquina superior)
- Página web del artículo
- Google Scholar (debajo del título)
- Bases de datos académicas
```

**Usando ISBN (International Standard Book Number):**

```
¿Qué es el ISBN?
- Identificador único de libros
- Formatos: ISBN-10 (viejo) o ISBN-13 (moderno)
- Ej: 978-0-06-245871-4

Cómo añadir por ISBN en Zotero:

1. Varita mágica (🪄)

2. Pegar ISBN (solo números, o con guiones):
   978-0-06-245871-4

3. Zotero:
   - Consulta WorldCat, Library of Congress, y otras
   - Recupera metadatos del libro
   - Crea item completo

4. Verificar y completar:
   - Edición (si hay múltiples)
   - Número de páginas
   - Lugar de publicación

Dónde encontrar ISBN:
- Contraportada del libro (código de barras)
- Página de derechos de autor
- Amazon, Goodreads
- Catálogos de bibliotecas
```

**Múltiples identificadores a la vez:**

```
Puedes pegar MÚLTIPLES DOIs/ISBNs en una sola operación:

1. Varita mágica (🪄)

2. Pegar lista (uno por línea):
   10.1371/journal.pone.0123456
   10.1016/j.socscimed.2020.113456
   978-0-06-245871-4
   10.17843/rpmesp.2017.344.2975

3. Enter

4. Zotero procesa todos secuencialmente

5. Útil cuando tienes:
   - Lista de DOIs de un review
   - Referencias de un paper que quieres importar
   - Bibliografía de un curso
```

**Añadir PDFs y extraer metadatos automáticamente**

**Método 1: Arrastrar PDF y extraer metadatos**

```
Proceso:

1. Ubicar PDF en tu computadora

2. Arrastrar PDF a Zotero:
   - Directamente a My Library (panel izquierdo)
   - O sobre una colección específica

3. PDF aparece como item sin metadatos

4. Click derecho en PDF → "Retrieve Metadata for PDF"

5. Zotero:
   - Extrae texto del PDF (OCR si es escaneado)
   - Busca DOI dentro del PDF
   - Consulta Google Scholar con título
   - Encuentra metadatos completos
   - Crea item padre con metadatos
   - Mueve PDF como adjunto del item

6. Resultado: Item completo con PDF adjunto

Tasa de éxito:
- PDFs con DOI: ~95%
- PDFs recientes sin DOI: ~80%
- PDFs antiguos/escaneados: ~40%
- PDFs de tesis: ~20%

Mejores prácticas:
✅ PDFs con texto seleccionable (no solo imagen)
✅ Primera página del PDF incluida (contiene metadatos)
✅ Archivo bien nombrado ayuda (Autor_Año_Título.pdf)

```

```
4. Seleccionar todos los PDFs en Zotero (Ctrl/Cmd + A)

5. Click derecho → "Retrieve Metadata for PDFs"

6. Zotero procesa todos secuencialmente
   (Puede tomar 5-15 minutos para 100 PDFs)

7. Revisar resultados:
   - PDFs con metadatos encontrados → Item completo
```

```
Smart Collections (Saved Searches):
- Colecciones que se actualizan automáticamente
- Basadas en criterios de búsqueda
- Se llenan solas cuando items cumplen condiciones

Ejemplo:
"Papers de últimos 2 años que mencionen 'Ayacucho'"

```

**Crear colecciones inteligentes:**

```

2. "New Saved Search"

3. Nombre: "Papers Recientes (2022-2024)"

4. Criterios:
   Match: all (todas las condiciones)
   
   Condition 1:
   - Field: Date
   - Condition: is in the last
   - Value: 3 years

   Condition 2:
   - Field: Item Type
   - Condition: is
   - Value: Journal Article

5. Save search

6. Colección "Papers Recientes (2022-2024)" aparece
   - Icono con lupa (🔍)
   - Se actualiza automáticamente

Ejemplos útiles para monografía:

BÚSQUEDA 1: "Papers sin leer muy relevantes"
- Tag → contains → muy-relevante
- Tag → does not contain → leido
```

**Operadores avanzados en Saved Searches:**

```
OPERADORES LÓGICOS:
- AND (todas las condiciones)
- OR (cualquier condición)
- NOT (excluir condiciones)

OPERADORES DE CAMPO:
- contains: contiene texto
- does not contain: no contiene
- is: es exactamente
- is not: no es
- is in the last: en los últimos X días/meses/años
- is before: antes de fecha
- is after: después de fecha

CAMPOS ESPECIALES:
- Attachment Content: busca dentro del texto de PDFs
  (requiere que Zotero haya indexado el PDF)
- Note: busca en notas personales
- Tag: busca por etiquetas
- Collection: busca en colección específica
- Date Added: cuándo se añadió a Zotero
- Date Modified: última modificación

EJEMPLOS AVANZADOS:

Buscar papers que mencionan "Ayacucho" en el PDF:
- Attachment Content → contains → Ayacucho

Buscar donde has escrito "metodología interesante" en notas:
- Note → contains → metodología interesante

Papers añadidos mientras leías un libro específico:
- Date Added → is after → 2024-10-01
- Date Added → is before → 2024-10-15
```

**Cronografías (Timeline) - Línea de tiempo visual**

```
¿Qué es la cronografía en Zotero?
- Visualización de tu biblioteca en línea de tiempo
- Eje X: Años de publicación
- Eje Y: Número de papers
- Útil para ver distribución temporal de literatura

Acceso:
1. Seleccionar colección
2. View → Timeline
   (O click en ícono de reloj en toolbar)

3. Visualización interactiva:
   - Barras por año
   - Hover sobre barra → ver items de ese año
   - Click en barra → filtrar biblioteca a ese año
   - Zoom in/out: rueda del mouse
   - Arrastrar: mover línea de tiempo

Usos prácticos:

USO 1: Verificar balance temporal
- Demasiados papers antiguos? → Buscar literatura reciente
- Muy concentrado en 1-2 años? → Ampliar búsqueda
- Objetivo: Distribución equilibrada (clásicos + recientes)

USO 2: Identificar gaps temporales
- ¿Hay periodo sin publicaciones? → Tema en declive o gap real
- ¿Pico reciente? → Tema de actualidad, más interés

USO 3: Contextualizar tu investigación
- Ver evolución del tema en el tiempo
- Identificar paper seminal (primer pico)
- Mapear desarrollo de conceptos

USO 4: Justificar revisión de literatura
En monografía:
"Se revisaron 50 artículos publicados entre 2010-2024,
con concentración en últimos 5 años (2020-2024: 32 artículos),
reflejando el creciente interés en el tema."

Ejemplo de análisis:
- 2010-2015: 8 papers (literatura inicial, conceptos básicos)
- 2016-2020: 15 papers (desarrollo metodológico)
- 2021-2024: 27 papers (aplicaciones recientes, contexto COVID)

Interpretación:
→ Tema en crecimiento
→ Relevancia actual alta
→ Justifica nueva investigación
```

```markdown
- Anemia es problema de salud pública en Perú, especialmente en sierra
- Programas deben focalizarse en zonas de altura y pobreza

- Muestra nacional representativa (N>18,000)
- Ajuste por altitud (crítico en Perú)
- Uso de ENDES (datos oficiales)

```

```
- Separar datos de programa

1. Cerrar Zotero completamente

6. Click "Choose..." → Seleccionar nueva ubicación

8. Verificar que todo funciona

9. Opcional: Eliminar carpeta vieja (después de verificar)

PRECAUCIÓN:
```

**Detector de duplicados de Zotero:**

```
Zotero detecta duplicados basándose en:
- Título similar (algoritmo de similitud)
- Autor(es) coincidentes
- Año de publicación
- DOI idéntico
- ISBN idéntico

Acceso al detector:

1. En library, ir a "Duplicate Items" (panel izquierdo)
   - Aparece automáticamente si hay duplicados
   - Si no aparece, no hay duplicados detectados

2. Zotero agrupa items duplicados

3. Por cada grupo:
   - Item "master" (más completo)
   - Item(s) duplicado(s)

Interfaz de duplicados:
┌──────────────────────────────────────┐
│ Duplicate Items (5 sets)             │
├──────────────────────────────────────┤
│ Set 1: "Prevalence of anaemia..."   │
│   Item 1: [Metadatos]                │
│   Item 2: [Metadatos]                │
│   [Merge 2 items]                    │
├──────────────────────────────────────┤
│ Set 2: "Determinants of..."         │
│   ...                                │
└──────────────────────────────────────┘
```

**Proceso de fusión de duplicados:**

```
Para cada set de duplicados:

1. Revisar ambos items lado a lado

2. Comparar:
   - Metadatos (¿cuál está más completo?)
   - PDFs adjuntos (¿cuál tiene PDF? ¿ambos?)
   - Notas (¿alguno tiene notas que no quieres perder?)
   - Tags (¿etiquetas únicas en alguno?)
   - Colecciones (¿en diferentes colecciones?)

3. Seleccionar item "master":
   - Click en item que quieres mantener
   - Zotero lo marca con estrella ⭐

4. Click en "Merge X items"

5. Zotero fusiona:
   ✅ Metadatos del master preserved
   ✅ Campos únicos del duplicado añadidos al master
   ✅ Todos los PDFs adjuntos combinados
   ✅ Notas de ambos combinadas
   ✅ Tags de ambos combinados
   ✅ Colecciones de ambos mantenidas
   ✅ Duplicado eliminado

6. Resultado: 1 item con toda la información combinada

Casos especiales:

CASO 1: Ambos items tienen PDF diferente
Resultado: Master tendrá AMBOS PDFs adjuntos
Acción post-merge: Verificar cuál PDF es correcto, eliminar el otro

CASO 2: Metadatos conflictivos (ej: años diferentes 2020 vs 2021)
Resultado: Zotero usa datos del master
Acción: Elegir master correcto ANTES de merge

CASO 3: Uno tiene notas extensas, otro no
Resultado: Notas se combinan automáticamente
OK: No se pierde información
```

**Mejores prácticas para duplicados:**

```
PREVENCIÓN:
1. Verificar antes de añadir:
   - Buscar en biblioteca antes de capturar nuevo item
   - Si ya existe, añadir PDF a existente en lugar de crear nuevo

2. Usar DOI cuando sea posible:
   - Varita mágica con DOI → Menos duplicados
   - DOI único garantiza no duplicar

3. Limpiar regularmente:
   - Cada 2-3 semanas, revisar "Duplicate Items"
   - No dejar acumular

DETECCIÓN MANUAL:
Si sospechas duplicados no detectados por Zotero:

1. Ordenar biblioteca por "Title"

2. Buscar visualmente títulos similares

3. Comparar manualmente

4. Eliminar duplicado manualmente o
   Relacionar items si no son realmente duplicados

BACKUP ANTES DE MERGE:
⚠️ Antes de fusionar muchos duplicados:
1. File → Create Timeline Snapshot... (No, esto no existe)
2. Mejor: Copiar carpeta Zotero completa como backup
3. Fusionar duplicados
4. Verificar que todo está bien
5. Entonces OK eliminar backup
```

**Renombrar PDFs automáticamente**

**Sistema de nombrado de Zotero:**

```
Problema: PDFs con nombres crípticos
- "document-12345.pdf"
- "fulltext.pdf"
- "main.pdf"
- "s41598-021-98765-4.pdf"

Solución: Renombrar según metadatos

Patrón de Zotero (default):
[Primer Autor]_[Año]_[Primeras palabras del título].pdf

Ejemplos:
- Gonzales_2017_Prevalence and determinants of anaemia.pdf
- Lopez_2020_Social determinants of child health.pdf
- Smith_2019_Anemia in high-altitude populations.pdf
```

**Renombrar PDFs:**

**Método 1: Individual**

```
1. Click derecho en PDF adjunto

2. "Rename File from Parent Metadata"

3. Zotero renombra automáticamente

4. Verificar: Hover sobre PDF → Ver nuevo nombre
```

**Método 2: Masivo (toda la biblioteca)**

```
1. Seleccionar múltiples items
   - Ctrl/Cmd + A (todos)
   - O seleccionar colección específica

2. Click derecho en selección

3. "Rename Attachments"

4. Zotero renombra todos los PDFs

5. Progreso mostrado en barra inferior

Tiempo: ~1 segundo por PDF
Para 100 PDFs: ~2 minutos
```

**Configuración automática de renombrado:**

```
Para que Zotero renombre automáticamente PDFs nuevos:

1. Edit → Preferences → General

2. Sección "File Handling"

3. ✅ Activar: "Automatically rename attachment files from parent metadata"

4. A partir de ahora:
   - PDFs nuevos capturados → Renombrados automáticamente
   - PDFs añadidos manualmente → Renombrados al añadirse
   - Metadatos actualizados → PDF renombrado automáticamente
```

**Personalizar patrón de nombrado (requiere plugin ZotFile):**

```
Plugin: ZotFile
GitHub: https://github.com/jlegewie/zotfile

Capacidades extendidas:
- Patrón personalizado de nombrado
- Mover PDFs a carpeta específica
- Extraer anotaciones de PDFs externos
- Renombrado más sofisticado

Patrones personalizados:
%a = Primer autor (apellido)
%y = Año
%t = Título completo
%s = Título corto
%j = Journal/Revista

Ejemplos:
{%a}_{%y}_{%t}
→ Gonzales_2017_Prevalence and determinants of anaemia.pdf

{%y}_{%a}_{%j}
→ 2017_Gonzales_Rev Peru Med Exp Salud Publica.pdf

{%a (%y)} {%t|50}
→ Gonzales (2017) Prevalence and determinants... [50 chars].pdf

Instalación y config de ZotFile:
1. Descargar .xpi desde GitHub releases
2. Tools → Add-ons → Gear icon → Install Add-on From File
3. Seleccionar .xpi descargado
4. Restart Zotero
5. Tools → ZotFile Preferences
6. Renaming Rules → Personalizar patrón
```

#### Lab: Anotar 5 PDFs y Crear Notas Estructuradas

**Duración:** 90 minutos (18 min por paper)

**Objetivo:** Dominar flujo completo de lectura, anotación y fichado

**Selección de papers:**

```
Elegir 5 papers de tu biblioteca que sean:
- Alta relevancia para monografía (#muy-relevante)
- No leídos aún (#no-leido)
- Con PDF adjunto
- Variedad de tipos (empírico, review, metodológico)
```

**Proceso para cada paper:**

**Fase 1: Lectura estratégica (10 min)**

```
1. Abrir PDF en lector de Zotero

2. Lectura rápida de estructura:
   - Abstract (completo)
   - Introducción (último párrafo)
   - Figuras y tablas principales
   - Primeras oraciones de cada sección
   - Discusión (completa)
   - Conclusión

3. Objetivo: Entender argumento principal sin leer todo
```

**Fase 2: Anotación activa (5 min)**

```
Con sistema de colores:

1. 🟡 AMARILLO: Resaltar hallazgos principales
   - Abstract: Resultado principal
   - Resultados: Datos clave
   - Mínimo 3 highlights

2. 🟠 NARANJA: Metodología
   - Diseño, muestra, instrumentos
   - Análisis estadístico
   - Mínimo 2 highlights

3. 🔴 ROJO: Para citar literalmente
   - Frases que usarás en tu monografía
   - Mínimo 1 highlight

4. 🟢 VERDE: Figuras/tablas importantes
   - Selección de área (Area tool)
   - Mínimo 1 figura

5. 📝 NOTAS: Comentarios críticos
   - Preguntas que surgen
   - Conexiones con otros papers
   - Críticas metodológicas
   - Mínimo 2 notas adhesivas
```

**Fase 3: Exportar anotaciones (1 min)**

```
1. Click en ⋮ → "Add Note from Annotations"

2. Nota generada automáticamente

3. Revisar nota generada
```

**Fase 4: Crear nota estructurada (2 min)**

```
1. Add → Add Note (nueva nota, separada de anotaciones)

2. Copiar plantilla de nota estructurada (proporcionada arriba)

3. Llenar secciones:
   - Resumen en una oración
   - Pregunta de investigación
   - Metodología (copiar de highlights naranjas)
   - Resultados (copiar de highlights amarillos)
   - Conclusiones
   - Fortalezas (2-3)
   - Limitaciones (2-3)
   - Citas clave (de highlights rojos)
   - Aplicación a monografía (CRÍTICO)

4. Tags: Añadir tags apropiados

5. Metadata: Fecha de lectura, prioridad
```

**Checklist por paper:**

```
□ PDF abierto y leído estratégicamente
□ Mínimo 10 highlights (código de colores)
□ Mínimo 2 comentarios en anotaciones

□ Nota estructurada creada y completa
```
